What this page is

This is the technical spec of the system that actually runs today, verified from source and receipts. It is deliberately separate from the proposed full architecture (L2 distillation/growth, two-model freeze/swap, ternary kernels, tiered paging), which is listed under “Not delivered” below. Every number here comes from the pinned source files and receipts linked in the trial index; parameter counts were computed from the exact source, not inferred from a model nickname.

The running pipeline

Frozen content encoder

  • Model: pinned SmolLM2-360M, float32, CPU-only, device placement attested in every receipt. Weights SHA-256 7aaff6661428bed0… (full 16-char prefix in every receipt; 361,821,120 parameters, all frozen).
  • Content key = last-token hidden state of a 48-token excerpt of a passage. Dimension: 960 (model hidden size, read from model config).
  • Encoder output cached per token-id SHA-256 (encP_<hash>.pt files); cache is persistence of encoder work, not the memory store.

Memory store

  • Store = growing set of (content key, label) pairs. Per entry: 960 float32 = 3,840 bytes plus label. Zero prompt tokens at inference.
  • Today's fixture store: 64 passages from 4 source works, anonymous labels; 16 held-out queries; shots n = 1/2/4/8; chance = 25%.

Kernel retrieval with adaptive bandwidth

  • Distances d&sub2;i = ‖keyi − query key‖²; normalised d̂²i = d&sub2;i / mean(d&sub2;) (the normalisation is the measured fix for softmax saturation at 960-dim distances, receipt8).
  • Weights wi = softmax(−β·d̂²i); retrieval feature r = Σ wi·keyi.
  • β = β1·n^α + β0, with β1, α, β0 learnable scalars. Trained values (receipt8, energy arm): β1 0.5847, α 0.5948, β0 0.0761 → β = 0.66 / 0.96 / 1.41 / 2.09 at n = 1/2/4/8.

Energy head (E21 mechanism, unrolled differentiably)

  • Latent z (ℓ = 4), feature ff = tanh(h · Fc), s = head(z + ff), v = s · qv.
  • Energy E(z) = s·(1 + z·qv + ½‖z‖²) + z·v + ½λ‖z‖².
  • K = 4 unrolled descent steps z ← z + step·(v + s·(z + qv) + λ·z), step = 0.1, λ = 0.1, norm clamp radius 2.0 (safe at z = 0). Each step carries create_graph=True so the classification loss reaches Fc/qv/head.
  • Prediction = out_head(concat(h, z + ff, r)) → 4 classes.

Training and timing boundaries (receipt8, measured)

  • Training: 60 Adam steps, lr 0.02, 8 passages per step, at n = 4. Energy arm: 2,176 head evals + 2,176 second-order gradient calls, 2.0 s wall. Direct arm: 2,176 head evals, 0 gradient calls, 0.7 s wall. Equal Adam steps is NOT equal compute.
  • Input: passage text → 48-token ids → 960-dim key. Output: one of 4 class labels. No text generation.

Not delivered (proposed, not built)

The original design intent (owner's Google Doc, 2026) is a two-model freeze/swap system: a frozen model codes a live model, then they swap roles, ping-ponging recursively; plus engram-style inactive states rewritten at inference, growing self-assembly with checkpoints, ternary CPU kernels, and tiered VRAM/RAM/NVMe paging. None of these is delivered. What runs today is a classifier fixture on top of a frozen encoder: retrieval + trainable heads. Marked explicitly: expert grafting — not delivered; freeze/swap — not delivered; ternary kernels — not delivered; tiered paging — not delivered; L2 growing-store distillation loop — not delivered; L3 matched-compute fine-tune comparison — not run. The zero prompt-token figure applies to the retrieval arm's inference path only, not to a total system cost.

Limitations of the current system

16 queries, 4 classes, one fixture, one 360M model, CPU. Best measured arm: 68.75% at 8 shots (receipt8) — margin over the direct head is 2 queries on 16. The shot curve is non-monotone (open defect). No language generation, no retention test, no held-out same-size superiority claim. External paper results (Memory Mosaics, VCNet, EBT, EB-JEPA) are source context, not our results.
