# Website publication gate for every new EXX experiment

The New AI site is a measured research log, not a leaderboard. A new experiment is **not published** until its own section, raw record, protocol, source and verdict are on the live site. No manual numbers in the HTML; the generator reads the immutable raw records.

1. Commit the protocol and executable runner before the outcome run. Keep failed runs and post-hoc revisions under separate IDs. Use validation only for choices; do not tune against a test split already inspected.
2. Add `results/EXX/summary.json` with per-seed raw outcomes, cohort/split and software/code provenance. The repository ignores `results/` by default; explicitly force-add only the intended summary, never the underlying licensed dataset. Attach the protocol, a candid report, runner and tests.
3. Extend `build_research_site.py` with a **task-specific** section: the primary task metric, a matched-control comparison, retention/old skill, parameter and compute costs, paired seeds and locked gate(s), uncertainties/failures and limitations. Visualize comparisons that share the *same dataset/metric*; never combine toy rule accuracy, text-classifier accuracy and language-model perplexity on one performance axis. E15 stays labeled as independent one-seed restarts, not a learning trajectory.
4. Add the experiment to `PUBLISHED_SUMMARIES`, the raw download and source-copy list, the top navigation, and a test for its gate and visuals. `check_publication()` **fails the build** whenever it finds a new `results/EXX/summary.json` that lacks a site entry. If the new experiment has no result file yet, do not announce it as run.
5. Run the entire `unittest discover -v` suite. Generate `research-site/` from the committed source. Check the exact numbers and SVG positions against raw JSON, verify accessibility (title/description, text alternatives), link targets and desktop/mobile visual layout in Helium. No chart should silently clip data, hide an overlapping arm, conflate a phase with a task cue, or imply comparable compute from equal optimizer steps.
6. Copy generated artifacts to a **new website branch/worktree**; open a PR, merge after review/tests, then fetch the live Pages URL. Compare deployed `index.html`, `data/eXX.json`, `source/EXX_REPORT.md` and the runner to the merge commit byte-for-byte. Only then post a concise result with the live link and an honest pass/fail table back into the New AI thread. If deployment or verification fails, state that it is not live yet.

E19 precedent: protocol `4f23317`, runner `ad1aa2d`, measured result `0cdc379`, website PR #4 at `e627574`. It **failed** feedback-vs-scheduled timing (0.00-point edge) and the new-task accuracy gate (59.15% vs required 65%). The additional graphics depict that failure; they do not change it. Future rounds must use their own preregistered acceptance criteria and fresh tests.
